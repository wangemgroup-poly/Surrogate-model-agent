# 仿真替代模型 Agent 使用说明

本工具用 CST 已有的全波结果训练替代模型，**在替代模型上做优化**，把候选设计连同预测一起冻结，再交给 CST 验证。它是一个本地命令行程序：**不需要 API key、不联网、不依赖任何云服务**。你可以手工运行，也可以让任意带终端能力的大模型助手按 [`../AGENTS.md`](../AGENTS.md) 来驱动它。

在线优化部分参考 Liu et al., IEEE TAP 2022（DOI 10.1109/TAP.2022.3211732），下称 SB-SADEA。

## 1. 它解决什么问题

在 CST 里直接做参数优化，每试一个设计就要跑一次全波求解。用已有结果训练出的替代模型，可以在几秒内对上万个候选打分，于是每一次宝贵的求解都花在"模型认为最有希望"的设计上。

本工具把这个闭环自动化，同时守住一条界线：

- **替代模型只负责提议**——候选的参数和预测值在任何求解启动之前就写入磁盘冻结；
- **CST 才有裁决权**——只有实测的全波结果能判定达标；
- 报告里的每个数字都能追溯到文件哈希、Run ID 和批次。

## 2. 环境要求与安装

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows（CST 结果库与宏执行器仅支持 Windows）|
| CST | CST Studio Suite 2025，**频域求解器**，参数化工程 |
| Python | 3.12（CST 2025 的 Python 结果库要求）|
| 依赖 | numpy、scipy、scikit-learn、joblib、threadpoolctl |
| 可选 | PyTorch，仅用于 SB-SADEA 的变分推断 BNN（`sb_sadea.surrogate = "bnn"`）|

```bat
setup.cmd                                  REM 用 py -3.12 创建 .venv 并安装依赖
setup.cmd "C:\完整的python3.12路径\python.exe"   REM py 启动器不可用时
```

`setup.cmd` 还会装 CUDA 12.6 版 PyTorch（无 GPU 时自动回落 CPU）；只用 GP 的话可以删掉那一行。

验证安装：

```bat
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

21 项测试应全部通过，且不需要 CST 和 GPU。

## 3. 五分钟上手（不需要CST）

```bat
.venv\Scripts\python.exe examples\demo_no_cst.py
```

脚本构造一个三参数的"虚拟结构"，把 60 组解析函数算出的数据当作全波结果导入，自动选模训练，再冻结一个 SB-SADEA 候选——即整个替代模型半环。任何机器都能跑，用来理解流程和目录结构。

## 3b. 引导式建任务（`setup`）

```bat
.venv\Scripts\python.exe agent.py setup                        REM 全部交互询问
.venv\Scripts\python.exe agent.py setup --project X.cst --lang zh
```

向导把手工写配置时最费时间的那些坑逐个过一遍：

1. **工程体检**——工程还开着就拒绝；报告有多少 Run 能读出参数；列出可用的一维结果树，
   让你从列表里选，而不是手打路径。
2. **同结构的其他版本**——扫描同目录下的其他 `.cst`，逐个告诉你是不是同一结构
   （几何文件**以及**固定参数取值）、各有多少 Run，并询问是否合并。
3. **参数范围**——同时显示优化器范围、已保存样本的实际范围和建议的并集；如果有数值参数
   在各 Run 之间变化却不是优化器参数，会标出来——否则导入会直接报错。
4. **定义目标**——取值方式、归约方式、频带、门限、误差尺度、罚函数权重。频带端点自动对齐到
   曲线的采样点，并检查频带是否落在仿真频率范围内；旁瓣类目标会去结果库确认切面是否真的存过。
5. **分段建议**——见下。
6. **数据量体检**——训练需要 `max(30, 3d)`、SB-SADEA 需要 `4d`，不够会告诉你还差多少。
7. 写出配置，然后可选地建任务并导入数据。**向导绝不启动求解器**，写入的预算是 0。

### 分段建议

对"全频带取最差值"这类目标，向导会读取每个已保存 Run 的曲线，找出**每个设计的最差点出现在哪个频率**。
如果这些位置很集中，整带作为一项目标就够了；如果在设计之间来回跳（通常是谐振点在带内移动），
向导会在聚集区之间的空隙处建议分段。

原因是可测量的：位置会移动的量，不是参数的光滑函数，替代模型因此预测不准，
而优化正是被一个比它所追求的改进量还大的误差牵着走。

你可以让向导**用你自己的数据实测**再决定：它对两种写法做交叉验证——都估计同一个物理量
（带内最差值），一种直接预测，一种取各子频带预测的最差值——把两个误差打印出来。
数字支持分段再采用。

### 向导查不了什么

网格收敛性、端口与边界是否正确、模型是不是你想要的结构。导入的历史 Run 没有求解日志，
所以**向导全部通过并不代表仿真设置在物理上是对的**，这部分判断仍然在你。

## 4. 完整流程

```
init ──► import-cst / import-json ──► train ──► propose ──► validate ──► 回填 ──► 再 train
                                                                   （run 命令自动循环）
```

**第一次对一个结构建任务，建议这样走：**

1. **找齐同一结构的所有工程版本。** 老版本工程里常常存着比新版本更好的结果。用
   `bounds --project A.cst --project B.cst` 看各自的优化器范围和并集。
2. **定参数范围。** 取"各版本优化器范围的并集"，再**并上这些工程里已保存样本的实际取值范围**——
   工程的优化器范围常在跑完一轮后被收窄，早期的好样本会落在当前范围之外，导入时被拒。
3. **确认频带端点。** 指标用 `"band": [f1, f2]` 时，f1 和 f2 必须正好是结果曲线的采样频点，否则提取会失败。
4. **`simulation_budget` 先写 0。** 这样无论如何都不会误启动求解。
5. `init` → `import-cst` → `train` → `propose`，把数据量、各项达标比例、当前最优、模型留出误差和第一个候选看清楚，再决定给多少仿真预算。
6. `run --rounds N --count 1 --budget N` 跑闭环。

## 5. 配置文件详解

模板见 [`../examples/config_template.json`](../examples/config_template.json)。

### 必填

| 字段 | 说明 |
|---|---|
| `schema_version` | 固定为 1 |
| `project` | 源 CST 工程 `.cst` 的完整路径 |
| `cst_install` | CST 安装目录，例如 `C:\Program Files (x86)\CST Studio Suite 2025` |
| `parameters` | `{"名称": [下限, 上限]}`。必须覆盖所有会变化的独立参数；固定参数不要列入 |
| `metrics` | 输出指标定义，见下 |

### 指标定义

**曲线类**（`"kind": "curve"`）：

| 字段 | 取值 | 说明 |
|---|---|---|
| `tree` | 例 `1D Results\\S-Parameters\\S1,1` | CST 结果树路径 |
| `transform` | `real` / `abs` / `db20` | 取值方式 |
| `reduce` | `max` / `min` / `ripple` / `at` | 频带内的归约方式；`at` 需配 `frequency` |
| `band` | `[f1, f2]` | 频带（GHz），端点必须是采样频点 |
| `op` + `limit` | `<=` `<` `>=` `>` + 数值 | 约束；不给则只报告不约束 |
| `scale` | 默认 1 | 误差归一化尺度，用于模型选择评分 |
| `penalty_weight` | 默认 1 | 罚函数权重，越大表示越不能违反 |

**方向图旁瓣类**（`"kind": "sll_phi_cut"`）：给 `frequency`、`phi`、`port`，从已保存的 φ 切面取最大峰与次大峰的功率比。

### 可选

| 字段 | 默认 | 说明 |
|---|---|---|
| `simulation_budget` | 0 | 任务生命周期内允许启动的求解总次数 |
| `cpus` / `timeout_minutes` | 16 / 45 | 隔离副本求解时的设置（不影响源工程）|
| `proposal_method` | `random_pool` | `random_pool` / `optimize` / `sb_sadea` |
| `search_domain` | `trust_region` | `optimize` 用：信任域内还是全参数域 |
| `sb_sadea` | `{"surrogate":"gp"}` | 还可设 `lambda`、`tau`、`F`、`CR`、`omega`、BNN 超参 |
| `include_global_gp` | false | 是否把全样本 GP 纳入候选算法（限 600 样本、20 输入、8 输出）|
| `trust_radius` / `search_pool` | 0.05 / 5000 | `random_pool` 的初始半径与撒点数 |
| `conservative_sigma` | 1 | `optimize` 的"预测最优"候选按 μ+kσ 判断约束 |
| `extrapolation_ratio` | 2 | 候选离最近样本超过该倍数的数据间距即标为外推 |
| `disagreement_limit` | 2 | 交叉核查分歧超过该值（按 scale 归一化）即标为"其他模型不支持" |
| `materialize` | `{"on":"improvement","max":3}` | 闭环中刷新最优时自动写回源工程；`on` 可取 `improvement`/`pass`/`never` |

## 6. 命令详解

统一形式：`.venv\Scripts\python.exe agent.py <命令> --task <任务目录> [参数]`。
直接运行 `run_agent.cmd` 会进入中文交互菜单。

| 命令 | 作用与要点 |
|---|---|
| `init --config` | 建任务；登记源工程文件哈希、几何签名、固定参数签名 |
| `bounds --project ...` | 只读打印各工程优化器范围及并集，建任务前用 |
| `inspect` | 导出 Run 列表、参数定义、结果树条目 |
| `import-cst [--project ...]` | 读取已保存的 Run。额外 `--project` 会先做结构校验再合并，样本 ID 加版本前缀 |
| `import-json --file` | 导入外部整理的全波指标（必须同结构、同求解设置）|
| `train [--force]` | 比较可用算法、选模、全量重拟合；数据与配置未变时沿用原模型 |
| `propose --count N` | 冻结 N 个候选（`sb_sadea` 只能为 1）|
| `seed --count N` | 无数据时的拉丁超立方初始采样计划 |
| `validate --budget N` | **会启动 CST**：隔离副本求解、校验、回填 |
| `resume --budget N` | 取消暂停并继续收集/验证 |
| `run --rounds R --count N --budget B` | **会启动 CST**：自动闭环，出现全部达标即停 |
| `pause` | 当前求解结束后暂停 |
| `discard` | 放弃尚未启动的候选 |
| `materialize [--design ID]` | **会启动 CST**：把已验证的设计写回源工程求解保存，便于在 CST 里看曲线 |
| `rebaseline` | 源工程只是新增了保存的 Run 时，重新登记其哈希 |
| `report` / `status` | 重新生成报告 |

## 7. 任务目录里有什么

```
tasks/my_task/
├─ config.json          目标、参数范围、方法、登记的签名
├─ data.json            全部入库设计：参数、指标、来源
├─ state.json           阶段、当前模型、当前批次、已启动求解次数
├─ events.jsonl         只追加的决策日志
├─ import_summary.json  各工程读入/入库/重复/拒绝/无结果数量
├─ bounds_advice.json   导入数据越界时的并集范围建议
├─ models/model_NNN/    model.joblib、selection.json（算法比较）、data_snapshot.json
├─ batches/batch_XXXX/  batch.json（冻结的预测）、cst/<候选>/（隔离工程副本）
├─ materialized.json    写回源工程的记录与逐项差值
├─ 报告.md / 报告.html   人读报告
└─ tradeoff.svg         约束取舍散点（无第三方绘图依赖）
```

**任务目录不要提交到 git**，里面全是你自己工程的绝对路径和全波数据（`.gitignore` 已排除）。

## 8. 怎么读报告

- **算法比较表**是验证集成绩，测试集只在选定算法之后评估一次，不参与选择。
- **留出误差**是按参数区域划分的离线误差，**不等于**对新设计的前瞻精度。报告在误差偏大时会明确写"只能用于引导补点，不能据其认证达标"。
- **候选批次表**列冻结预测、CST 实测和"实际减预测"，以及外推/模型分歧预警。
- **约束取舍**一节列出各指标的全体最优，以及"其余约束都满足时"的最优——两者差距大，说明存在取舍。
- **参数边界**一节统计前 10 名和 Agent 候选中压在范围边界的参数；持续触边说明范围限制了优化。
- **收敛**一节给出已验证设计的最差归一化余量走势和最近一次改进的位置。

## 9. 调优手段

| 现象 | 处理 |
|---|---|
| 搜索总是牺牲某项指标 | 给该指标加 `penalty_weight`（2–3），重新训练与生成候选 |
| 最优设计持续压同一个边界 | 放宽该参数范围——范围变化必须**新建任务** |
| 候选离数据太远、预测过于乐观 | 调大 `conservative_sigma`；或把 `search_domain` 从 `full` 改回 `trust_region` |
| 轮次波动大 | 数据跨多个不相干区域时容易如此；可考虑减小 `sb_sadea.lambda`（偏离论文默认值）|
| 某项指标预测特别不准 | 若该项余量很大可以忽略；若它是瓶颈，考虑把宽频带指标拆成子频段分别建模（论文的"精细监督"思路）|

## 10. 安全机制

- 源工程必须**关闭**（无 `Model.lok`）才允许复制或求解。
- 身份在 `init` 时登记，每次求解前复核：几何文件（`Model.mod`、`ModelHistory.json`、求解属性）**以及任务未优化的全部固定参数取值**。新增保存的 Run 不影响；改了固定尺寸或几何则拒绝。
- 候选在**隔离副本**中求解，不复制旧结果与网格缓存。
- 求解后检查：宏返回值 1、`DONE` 标记、进程退出码 0、日志中的宽带收敛、参数逐项回读。
- 双预算：任务总预算与本次 `--budget` 同时生效。
- 求解失败或被中断**不会自动重试**，现场原样保留，供诊断后由人决定。
- 每个任务一把写锁。
- 改预算、CPU 数、等待时限**不会**作废已训练模型和已冻结批次；改目标、参数范围、挑点方法会。

## 11. 常见问题与故障处理

**导入报"已有数据中还存在变化的独立参数"**
工程里有参数在各 Run 之间变化但没列进 `parameters`。把它加入参数表，或筛掉那些 Run。

**导入时大量样本被拒**
样本落在任务参数范围之外。看 `bounds_advice.json` 给的并集建议，用更宽的范围**新建任务**。

**`import-cst` 拒绝合并另一个工程**
错误信息会说明原因：几何文件不同、固定参数定义不同、或固定参数取值不同。几何历史相同不代表同一模型——固定尺寸存在 `Parameters.json` 里，不在几何文件中。

**中文路径报编码错误**
CST 的 Python 结果库打不开非 ASCII 路径。Agent 会自动在 `C:\Users\Public\Documents` 下建只读目录联接并经由它访问，无需手工处理。

**求解失败，候选卡在 running**
先看 `batches/*/cst/*/job.json`、`status.txt` 和 `project/Result/Model.log`：
- 日志里"Full rebuild failed"→ 这组参数几何不合理；放弃该候选。
- 几何重建、划网、端口计算都正常却中途退出 → 多半是外部原因（有人关掉了 CST、许可证冲突）。可以把崩溃的副本目录移到别处保留，让候选回到 `pending` 再跑一次（消耗 1 次预算）。
Agent 故意不自动重试，以免重复消耗预算。

**写回时报路径太长**
CST 结果树很深，备份路径可能超过 Windows 260 字符上限。Agent 复制时已使用扩展长度路径；如仍失败，把任务目录放到更浅的位置。

**训练报"样本不足以分组验证"**
样本数少于 `max(30, 3×参数数)`。先导入更多数据，或用 `seed` + `validate` 在明确预算内补点。

**SB-SADEA 报"数据库样本少于λ或τ"**
样本数少于 `4×参数数`。补数据，或在 `sb_sadea` 里调小 `lambda`/`tau`（偏离论文设定，应记录说明）。

## 12. 已知局限

- 仅支持 CST 参数化**频域**工程；其他求解器需要新写适配器。
- 指标只来自你指定的结果树和已保存的 φ 切面；旁瓣按切面最大峰与次大峰之比定义。
- **不确定度未校准**：σ 是模型离散度，不能解释为合格概率。
- 换结构必须新建任务，模型不可跨结构复用。
- 离散频点达标不等于频带内处处达标。
- "未找到达标方案"只意味着"在当前参数范围与预算内没找到"。
- 替代模型的上限由数据覆盖决定：优化前请把同一结构**所有版本**的结果都收齐。

## 13. 与论文的差异

- 已有全波数据时跳过论文的拉丁超立方初始化。
- 论文未说明隐藏层激活，本实现取 tanh；不确定度仅来自权重采样。
- 论文接受稿印刷的 τ=4 按正文"至少 4×d 个训练点"理解为 τ=4d。
- 论文式(11) 未说明 KL 项如何缩放：按字面取 KL 权重 1 时，小样本下网络会退化为近邻均值；因此提供 `kl_weight` 参数（默认 1 保持字面）。
- 默认局部代理为 GP（对应论文表 III 的 GP-ALCB 变体，ω=2），BNN 作为可选（ω=14）。
- 未实现论文的"精细监督"。
- 罚函数适应度按论文式(16)(17)，各指标权重可配置。
